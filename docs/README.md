# Documentation

Start with [product.md](product.md): what Engwire is, the routine it automates today, what is being proved, and the rules for deciding what to build next. Read [architecture.md](architecture.md) for the invariants and module boundaries the implementation obeys today. Use a focused [specification](specs/) for current product behavior that needs more detail, and an [ADR](adr/) when the history and tradeoffs behind a durable decision deserve their own record; each directory contains its convention and template.

- [experiments.md](experiments.md) records measured behavior of the external systems Engwire relies on.
- [SECURITY.md](../SECURITY.md) defines the trust model and security boundaries.
- [explorations/](explorations/) holds future designs. They are explicitly non-binding — never cite one as a requirement.
